# Node port — 02-10-2026

**Why:** User asked to collapse the multi-phase Python repo into a single Node.js project.
Python worked end-to-end but living in seven directories with separate `requirements.txt` files made the project hard to ship and hard to integrate with the Node-native toolchain the user already had.
Goal: one `npm install`, one `npm start`, same wire behavior.

---

## What was swapped

### HTTP client: `requests` + `curl_cffi` → `cycletls`

Python used `requests` for unauthenticated calls and `curl_cffi` (Chrome impersonation) for anything that touched Hatch's TLS-fingerprinted endpoints.

Node replacement: **cycletls** with `ja3: <Chrome 154 fingerprint>` on every Hatch HTTP call.
The Hatch WebSocket upgrade goes via Node's native `globalThis.WebSocket` — cycletls exposes no user-facing WebSocket API, so the WS path stays on the standard Node WS stack.
Whether Hatch enforces JA3 on the WS upgrade is still unknown; Task 20 E2E will validate.

### Noise XX: `dissononce` → hand-rolled on `@noble/*`

Python used the `dissononce` library (a full Noise framework).
Node replacement: hand-rolled Noise XX in `src/noise/` using:
- `@noble/curves` — X25519 DH
- `@noble/ciphers` — AESGCM encryption/decryption
- `@noble/hashes` — SHA-256 HKDF

No Noise framework dependency added. The XX pattern is short enough (3 messages, split cipher states) that rolling it is less surface than carrying a framework.

### Protobuf: `google.protobuf.descriptor_pb2` + `DescriptorPool` → `protobufjs` `Root.fromDescriptor`

Python loaded the 5 extracted `.binpb` FileDescriptorProto files via `DescriptorPool`.
Node replacement: `protobufjs` `Root.fromDescriptor` in `src/proto/loader.ts`, loading the same binary files from `src/proto/schemas/*.binpb`.
Hand-typed message shapes in `src/proto/types.ts` for the types used at runtime (avoids generated-code churn).

### HTTP server: `FastAPI` + `uvicorn` → `Hono` + `@hono/node-server`

Python served the OpenAI/Anthropic proxy via FastAPI.
Node replacement: **Hono** with `@hono/node-server`, listening on `127.0.0.1:8787`.
Same routes: `POST /v1/chat/completions`, `POST /v1/messages`, `POST /v1/messages/count_tokens` (stub), `GET /healthz`.

### Logging: print/logging → `pino`

`pino` added for structured JSON logs with level filtering via `LOG_LEVEL` env var.
No previous logging library to swap out — Python used bare `print()` calls.

### Env validation: no equivalent → `zod`

`zod` added in `src/config.ts` to validate required env vars at startup (fails fast with a clear error instead of a cryptic runtime crash deep in the client).

## Gotchas carried over from Python

**Chrome TLS JA3 impersonation required.**
Hatch's authenticated HTTP endpoints (bootstrap calls, Hatch API) return 403 on stock TLS fingerprints.
cycletls with `ja3: <Chrome 154 fingerprint>` + pinned `User-Agent` and `sec-ch-ua` headers (matching the browser session was minted in: Windows Chrome 154) is required for every Hatch HTTP call.

**UA must match the session cookie's browser.**
The session cookie minted by `storage_state.json` is bound to the UA string used at login.
If you dump cookies from Chrome 154 on Windows, the proxy headers must also claim Chrome 154 on Windows.

**`snake_case` protobuf field names — the plan was wrong.**
The original design doc assumed protobufjs would emit camelCase field names (its default for `.proto` files).
Loading from binary `FileDescriptorProto` blobs via `Root.fromDescriptor` preserves the original wire names, which are `snake_case`.
All field accesses in `src/proto/` and `src/hatch/` had to be written as `snake_case` to match.

**48 KB NoiseTransportFrame chunking for large payloads.**
Hatch's Noise layer has a per-frame payload limit (~65 KB raw, ~48 KB after encryption overhead).
Large HTTP-over-Noise requests — particularly Claude Code's system prompts which can be 50–200 KB — must be split across multiple `NoiseTransportFrame` messages before sending.
The Python code discovered this in Phase 7; the Node port carries the same chunking logic in `src/hatch/transport.ts`.

**Node WS doesn't apply JA3 to the WS upgrade.**
cycletls handles TLS fingerprinting for HTTP calls.
The Noise WebSocket upgrade goes through Node's native `WebSocket` (no cycletls WS API).
It is currently unknown whether Hatch enforces TLS fingerprint on the WS upgrade handshake.
Task 20 E2E will confirm. If enforcement is added, a JA3-capable WS client will be needed.

## What's new in the Node port

**zod env validation (`src/config.ts`).**
Startup fails immediately with a human-readable error if required env vars (e.g. `SESSION_PATH`) are missing or malformed.

**pino structured logging (`src/log.ts`).**
Every layer (bootstrap, noise, hatch, server) logs via a named child logger.
Set `LOG_LEVEL=debug` to see raw frame bytes and HTTP-over-Noise round-trips.

**Mock-based unit tests throughout.**
`tests/*.test.ts` use Node's built-in `node --test` runner with mock dependencies — no test framework added.
Coverage: noise frame encode/decode, proto loading, hatch client happy path, server route shapes.
